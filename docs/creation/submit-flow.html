To confirm with the PL/SQL team
Points in the breakdown that look unexpected, or that the Angular build needs a decision on.

  

    
Property insert columnsThe property INSERT lists the insurance columns (POLICY_TYPE, INS_COMPANY, INS_CODE, POLICY_NO). Location, ownership, forced sale value, valuer and valuation date are validated but not inserted. Which columns does the real code write?

    
Comments before the checkPRC_APPROVAL_COMMENTS runs before RESPONSE_CODE is checked. If the request fails, are the comments left behind?

    
Delete then insertStep 5 deletes any row with the same collateral number before inserting. This is what lets a returned request be resubmitted, but it also drops the earlier row's history.

    
Fields saved but not requiredInsurance saves POLICY_NO without requiring it. Guarantee saves the account and the underlying collateral type without requiring them. Should they be required?

    
Approval request IDIs APPSEQ_V returned by PRC_APP_ENQ, or generated before the call?

    
Typos in the breakdownShares inserts FOLIO_START_N, and its block is titled "submit guarantee collateral". Probably copy slips. Confirm against the source.
