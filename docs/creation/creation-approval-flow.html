From Submit to Approved

How a new collateral moves through Oracle Forms today, read from the two PL/SQL triggers: the officer's Submit on the Creation screen, and the approver's Approve on the Approval screen. The row in TB_COLLATERAL is created as APPROVAL_FLAG = 'N' and turned to 'Y' when approved.

To confirm with the PL/SQL team
Points in the two triggers that look unexpected, or that the Angular build needs a decision on.

  
Approval

  

    
Response codesSubmit checks for S; approve checks for F and Y. Any other code skips the update but still audits, commits and shows "Record Saved." Does it mean another approval level is needed?

    
Lien not placedThe LIEN insert and G_LEDGER lien update are commented out. Is the lien placed somewhere else? If they are switched back on, the insert should filter by COLLATERAL_NO: today it selects every row on the account.

    
Hard-coded valuesThe approve call passes currency '010' and a NULL amount, whatever the collateral's currency and amount.

    
Four reads of one rowFour SELECTs fetch one row by APP_REF. One query would do, and none handles "no row found".

    
No reject pathThis trigger only approves. The new design adds Return and Dismiss with reasons. Where should those be stored, and does PRC_APP_ENQ have a reject mode?

    
Audit detailThe audit passes NULL for the description and the collateral type. Should the Angular build record the collateral number and type?

  

  
Creation

  

    
Property insert columnsThe property INSERT lists the insurance columns (POLICY_TYPE, INS_COMPANY, INS_CODE, POLICY_NO). Location, ownership, forced sale value, valuer and valuation date are validated but not inserted.

    
Comments before the checkPRC_APPROVAL_COMMENTS runs before RESPONSE_CODE is checked. If the request fails, are the comments left behind?

    
Delete then insertStep 5 deletes any row with the same collateral number before inserting. This allows resubmission but drops the earlier row's history.

    
Fields saved but not requiredInsurance saves POLICY_NO without requiring it. Guarantee saves the account and the underlying collateral type without requiring them.

    
Approval request IDIs APPSEQ_V returned by PRC_APP_ENQ, or generated before the call?

    
Typos in the breakdownShares inserts FOLIO_START_N, and its block is titled "submit guarantee collateral". Probably copy slips.
